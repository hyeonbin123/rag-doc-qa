## 누가 썼나 (질문)

- 2026-10-15, 별도의 LLM 에이전트(Claude, 이 저장소 작업을 맡은 에이전트가 띄운 하위 에이전트)가 썼음
- 오염 통제: 그 에이전트에게 준 지시는 다음뿐임. 기계의 어떤 파일·폴더도 읽거나 찾지 말 것(이 저장소와 FastAPI 문서 포함), 웹 검색·웹 가져오기를 쓰지 말 것, 쓸 수 있는 도구 호출은 위 네 파일을 쓰는 것뿐. 에이전트의 도구 호출은 파일 쓰기 4번이었음(실행 기록의 호출 수로 확인). 받은 맥락은 "FastAPI 공식 문서(영어와 한국어 번역)만 근거로 답하는 RAG 도우미에 개발자가 칠 만한 질문, 일부는 문서가 다루지 않을 것 같은 질문"이라는 설명뿐임
- 그래도 그 모델은 학습으로 FastAPI 문서를 알고 있음. 질문 풀 3과 같은 한계임
- 글쓰기 지시: 영어는 한국어를 옮기지 말고 따로 쓸 것, 한국어는 번역투가 아니게, 짧은 사용법·증상 설명·개념·비교·오류 메시지를 섞을 것, 목차를 따라가지 말 것, 한 파일 안에서 중복 없이

## 라벨 (2026-10-15, 질문 커밋 `f0c1635` 뒤)

- **누가**: Claude Code 하위 에이전트 네 개가 나눠 붙였음(한국어 k4001~k4055 / k4056~k4110 + 인접 30 / 영어 e4001~e4055 / e4056~e4110 + 인접 30). 모두 같은 지침을 받았음
- **본 것**: 질문 파일 네 개와 코퍼스 스냅숏(FastAPI 커밋 `50113da16fec53b66b80d75e80a89296de4fa5a5`의 Markdown, DB에 적재된 277개 문서 목록 안의 파일)뿐. grep과 읽기로 사람이 문서를 찾듯 찾았음
- **오염 통제** (지침으로 금지, 질문 풀 3보다 엄격): 어떤 검색 시스템·DB·임베딩 모델·LLM·평가 스크립트도 돌리지 않음. `eval/`의 다른 파일, `docs/experiments.md`, 평가 기록·리포트, README, 다른 라벨러의 출력은 열지 않음. 그래서 질문 풀 3의 라벨러와 달리 이전 실험에서 어떤 질문이 실패했는지 모르는 상태였음(지침으로 전달한 조건이고, 도구 사용 기록을 하나하나 확인하지는 않았음)
- **규칙**
  - `answerable: true`: 코퍼스 페이지 본문만으로 질문의 핵심에 답할 수 있음. 답하는 페이지를 모두 `expected_source_paths`에 적음(지나가는 언급만 있는 페이지는 뺌). 한국어 질문은 번역이 있으면 한국어 경로, 없으면 영어 경로
  - `answerable: false`: 영어·한국어 트리에서 식별자·동의어로 세 가지 이상 찾아도 핵심에 답하는 페이지가 없음. 찾은 내용을 `not_in_docs_evidence`에 적음. 질문을 쓴 쪽의 의도(본 파일/인접 파일)가 아니라 문서로 정함
  - `dropped`: 공정하게 라벨을 붙일 수 없는 질문(쓰지 않았음)
  - 참고 답안은 문서 내용을 옮기지 않고 요약함. 정답 페이지가 여럿이면 각 페이지가 보태는 내용을 참고 답안에 모두 넣음(질문 풀 3의 t030 문제를 피하려고). 답 없는 질문의 참고 답안은 '공식 문서가 다루지 않으며 그렇다고 밝히는 답이 맞다'이고, 바로 관련된 문서 내용이 있으면 한 구절 덧붙임
- **결과** (`eval/pool4_labels.jsonl`, 280줄)

  | | 본 파일 (110) | 인접 파일 (30) |
  |---|---|---|
  | 한국어 | 답 있음 110 | 답 없음 30 |
  | 영어 | 답 있음 110 | 답 없음 30 |

  - 뺀 문항 0개. 질문을 쓴 쪽의 의도와 라벨이 모두 일치함
  - 답 있는 문항의 정답 페이지 수: 1개 176, 2개 36, 3개 6, 4개 1, 6개 1. 영어 전용 페이지가 정답인 한국어 문항 0개
- **확인** (스크립트, 문서 내용은 보지 않음): 질문 문장이 풀 파일의 그 줄과 280개 모두 같음, 모든 정답 경로가 277개 문서 목록 안에 있음, 모든 `evidence` 앵커가 그 파일에 `{ #앵커 }`로 있음, 답 없는 문항은 정답 경로·앵커가 비어 있고 검색 기록이 있음
- **판단이 갈릴 수 있는 문항** (라벨러가 `notes`에 적음)
  - 일부만 답하는 질문을 답 있음으로 둔 것: `e4047`(Annotated 권장은 답하지만 오래된 Python 지원은 다루지 않음), `e4036`(`exclude_defaults`·`exclude_none`은 이름만 소개), `e4063`(전체 URL 얻기는 Starlette 문서 링크뿐), `e4083`, `k4001`(블로킹 호출의 결과는 문서 설명에서 추론)
  - 보조 페이지를 정답에 더한 것: `k4037`, `k4046`, `k4052`, `k4058`, `k4068`, `k4083`, `k4093`, `e4003`, `e4006`, `e4016`, `e4057`. `e4067`은 `release-notes.md`(`regex` → `pattern`)를 정답에 넣었지만 그 파일에 앵커가 없어 근거 앵커는 튜토리얼 쪽만 있음

## 한계

- 질문을 LLM이 썼으므로 실제 사용자 질문의 분포·말투와 다를 수 있음(질문 풀 3과 같음)
- 답 없는 질문은 모두 '인접 주제'(다른 프레임워크, 특정 클라우드 콘솔 절차, 서버 설정값 등)로, 문서가 다루는 주제와 비교적 분명히 떨어져 있음. 문서가 거의 다루지만 핵심 하나만 빠진 '가까운 답 없음' 질문은 이 풀에 없으므로, 그런 질문의 거절은 이 풀로 잴 수 없음
- 라벨러는 문서를 본 상태임. 이전 결과는 보지 않았지만, 정답 페이지 판단이 사람과 다를 수 있음
